0. Verse8 환경 확인 결과 (공식 문서 기준)

확인 출처 — docs.verse8.io/ko/docs 및 하위 문서를 직접 조회함.
  • 기본 스택: npm create vite@latest my-app -- --template react-ts + npm install @agent8/gameserver (Node 18+). 즉 Vite + React + TypeScript가 공식 전제. → 요청하신 전제와 일치.
  • 서버: 프로젝트 루트에 server.js, class Server { } 형태. export 금지 (module.exports/export default 사용 불가). 파일명 고정.
  • 내장 변수: $global(전역 상태·컬렉션), $room(룸 상태), $sender(요청자 account/roomId/guest 여부).
  • setTimeout / setInterval 사용 금지 → 반복 로직은 $roomTick(deltaMillis, roomId) 사용. 클래스 레벨 변수는 요청마다 초기화되므로 상수 용도로만.
  • 클라이언트 호출: useGameServer() 훅 → server.remoteFunction("fn", [args]). 표준 호출 약 10회/초 제한, 고빈도(이동 등)는 throttle + throttleKey, 반환 불필요 시 needResponse:false.
  • 배포: npx -y @agent8/deploy → VITE_AGENT8_VERSE 환경변수 생성.
  • Leaderboard: 별도 서비스가 아니라 GameServer 컬렉션 기반. submitScore() / getTopRankings()(상위 20) / getMyBestRank() / getMyAllRankings()를 server.js에 구현. → 리더보드를 쓰면 Game Server + Auth가 자동으로 세트.
  • Auth: @verse8/platform의 Verse8.getUser() — URL ?auth= 토큰 파싱·서명 검증.
  • Local Cache: @verse8/local-cache, best-effort. 진행도·인벤토리 저장 금지(언제든 삭제될 수 있음). 용도는 시드 기반 지형, 디코딩된 에셋, 룩업 테이블 등 재생성 가능한 데이터. 게임당 64MB soft cap.
  • Ads: @verse8/ads — showRewarded() 결과 rewarded/dismissed/failed. 반드시 유저 제스처로만 호출, 보상값은 UX 힌트일 뿐이므로 가치 있는 보상은 서버에서 requestId 검증.
  • VXShop: 서버 이벤트 핸들러 $onItemPurchased(data).
설계 원칙 (아래 10개 전부 적용) — 영구 진행도는 Local Cache가 아니라 Global User State에, 반복 서버 로직은 $roomTick에, 렌더링 라이브러리는 Vite 번들에 그대로 들어가므로 Phaser/Pixi/Three 모두 배포 구조와 충돌 없음(전부 클라이언트 사이드).

핵심 재미
맵을 매판 셔플하고 웨이브마다 "골드 2배 위험 웨이브 / 안전 웨이브" 선택을 넣어, 같은 맵이라도 리스크 선택이 달라진다. 판당 5~8분.

  • Leaderboard: 사용 — 최고 도달 웨이브
  • Local Cache: 미사용 · Room: 미사용(싱글) · VXShop: 미사용
  • Ads: 선택적 — 게임오버 시 1회 부활 (보상은 서버에서 requestId 검증)

racing-kit · car-kit · skyboxes
CC0 확인

에셋→게임 도출
Racing Kit이 모듈형 트랙 타일이라는 점이 결정적이다. 타일을 배열로 이어 붙이면 트랙이 만들어지고, 같은 배열로 주행 경로(스플라인)를 자동 생성할 수 있다 → 레벨 디자인 비용이 0이고 트랙을 코드로 무한 생성할 수 있다. 3D 에셋으로 만들 수 있는 것 중 추가 아트가 가장 덜 드는 장르가 레이싱인 이유.

모바일 조작

React + TypeScript + Three.js — glTF 3D 모델을 그대로 로드. 물리는 아케이드 차량 모델(속도·조향각·그립)을 직접 구현해 물리엔진 의존 제거 → 번들 가볍고 결정론적이라 고스트 재현이 정확.

부분 확인 — itch 라이선스 필드 "Creative Commons Zero v1.0 Universal". 다만 본문에 팩 자체의 재배포 자제 요청이 병기되어 있어, 후보 중 유일하게 문구가 완전히 깔끔하지는 않음. 게임 내 사용은 문제 없음.
에셋→게임 도출
주인공 애니메이션이 10종이나 갖춰졌는데 적은 2종뿐이다. 이 비대칭이 장르를 결정한다 — 적 다양성이 필요한 액션 캠페인은 불가능하고, 플레이어 동작이 주인공이고 적은 장애물 역할인 러너/플랫포머가 맞다. 3레이어 패럴랙스는 스크롤 속도감을 위해 그려진 것이라 러너와 정확히 같은 목적이다.
Core Loop
자동 전진 → 점프/슬라이드/공격 → 청크 통과 → 속도 상승 → 사망 → 거리 기록 → 스킨 해금
플레이 방식
가로 스크롤. 미리 만든 20~30개 구간 청크를 난이도순으로 랜덤 연결. 속도가 계속 올라간다. 목표는 최장 거리.
핵심 재미
손맛 있는 픽셀 애니메이션 + 30초~2분 초단타 세션. 실패 즉시 재시작.
PC 조작
Space 점프 · ↓ 슬라이드 · 좌클릭/X 공격
모바일 조작
화면 좌측 탭 = 점프, 우측 탭 = 공격, 아래 스와이프 = 슬라이드
기술 구조
React + TypeScript + PixiJS — 타일 청크 재활용 스크롤 + TilingSprite 패럴랙스가 기본 기능으로 제공. (원본에 Phaser 데모가 있어 Phaser도 가능하나, UI를 React로 붙일 거면 Pixi가 더 가벼움)

12. 최종 추천

가장 빠르게 제작 가능 07 DAILY CRATE — 상태가 2차원 배열 하나, 캔버스도 물리도 불필요. 에셋이 규칙 전용으로 그려져 있어 디자인 결정조차 거의 없다. 하루 이틀이면 배포 가능한 수준.
에셋 완성도가 가장 높음 06 CRAWL TACTICS (2D 기준) — 몬스터·아이템·이펙트·GUI까지 3,000+ 타일. 콘텐츠를 아무리 늘려도 그래픽이 먼저 바닥나지 않는다.
3D 기준으로는 05 BONE ARENA — 리깅·애니메이션된 캐릭터 9종 + 무기 35종 + 모듈 던전 200개가 단일 아트 스타일로 통일되어 있다.
추가 에셋이 가장 적게 필요 01 STEEL LINE — 타워 베이스/헤드 분리, 경로 타일, 적 유닛, 폭발까지 한 팩에 다 있고 UI는 Kenney UI Pack이 그대로 붙는다. 새로 그릴 것이 사실상 없음.
모바일에 가장 적합 02 VOID DRIFT — 조작이 "한 손가락 드래그" 하나뿐이고 사격은 자동. PC의 마우스 추종과 동작이 완전히 같아 두 플랫폼이 다른 게임이 되지 않는다. 세로 화면과도 맞음.
Verse8 기능과 가장 잘 어울림 06 CRAWL TACTICS — $global에 일일 시드를 두고 전 유저가 같은 조건에서 경쟁 → Global State와 Leaderboard가 억지가 아니라 게임의 핵심 규칙 자체다. Game Server가 시드 발급과 점수 검증을 동시에 맡아 서버 구조도 단순.
수익화 기능까지 포함하면 08 MINI DINER가 Ads·VXShop·Global User State를 전부 자연스럽게 쓴다.
반복 플레이 가능성이 가장 높음 03 CRYPT WAVE — 판당 5~10분, 사망이 곧 영구 강화 재화, 매판 다른 빌드. 장르 자체가 반복을 전제로 설계된 구조.
전체 추천 02 VOID DRIFT — 이유 세 가지. (1) 에셋 295개가 손상 단계 스프라이트까지 갖춰 추가 제작이 0에 수렴한다. (2) 구현 난이도가 낮은데 결과물이 "완성된 게임"으로 보인다 — 작지만 완성도 높은 게임이라는 조건에 가장 정확히 맞는다. (3) Leaderboard + Ads 컨티뉴가 Verse8 기능을 억지 없이 쓰고, PC/모바일 조작이 동일하다.

차순위: 01 STEEL LINE(가장 안전한 선택), 06 CRAWL TACTICS(Verse8 기능 활용도 최고, 콘텐츠 확장 여력 최대).
