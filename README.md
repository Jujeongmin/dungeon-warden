# DUNGEON WARDEN

던전 관리자가 되어 방을 파고 함정을 놓고 스켈레톤을 배치해, 몇 번이고 다시 찾아오는 모험가 파티를 막아내는 저장형 던전 경영 게임.

Verse8(Agent8) 플랫폼 배포 대상. Vite + React + TypeScript + Three.js.

## 현재 상태: M7 — 연출 · 직업 확장

- [x] **모험가 5직업** — 기사 / 바바리안 / 로그 / 메이지 / 레인저, 각각 다른 문제를 냄
- [x] **전투 피드백** — 데미지 숫자, 피격 플래시, 함정 발동 링, 처치/생포 표시
- [x] **애니메이션 배선** — 모델에 클립이 있으면 idle/walk/attack/death 자동 연결

- [x] **KayKit 에셋 투입 완료** — 모델 21개 키 전부 매칭, 애니메이션 연결됨

### 모험가 5직업

같은 던전(워리어 1 + 가시 2)에 각 직업을 넣고 측정한 결과입니다.

| 직업 | 소요 | 남은 체력 | 받은 함정 피해 | 피격 횟수 | 성격 |
|---|---|---|---|---|---|
| 기사 | 14.0초 | 31 | 36 | 9 | 기준점 |
| 바바리안 | 11.8초 | 14.6 | 41 | 8 | 부하를 가장 빨리 부수지만 자기도 얇음 |
| 로그 | 11.3초 | 5.8 | **16** | 9 | **함정을 거의 무시** — 함정만 깐 던전의 천적 |
| 메이지 | 16.6초 | 26.8 | 43 | **2** | 사거리 3.0으로 **워리어가 손도 못 댐** |
| 레인저 | 14.2초 | **44** | 36 | **2** | 사거리 3.8로 안전하게 정리 |

핵심은 **같은 던전이 직업마다 다르게 깨진다**는 점입니다. 함정만 깔면 로그에게,
근접 부하 하나만 두면 메이지·레인저에게 뚫립니다. 위협도가 오를수록 직업이
차례로 합류하므로(기사 → 바바리안 → 로그 → 레인저 → 메이지), 초반 던전은
기사만 상대합니다.

원거리 직업은 **가장 가까운 부하가 아니라 사거리 안에서 가장 먼 부하**를
노립니다. 워리어 뒤에 숨겨 둔 메이지가 저격당하는 이유입니다.



### 전투 연출

`RaidSim`이 그리지 않고 **보고합니다.** 스텝마다 이벤트 목록을 쌓고
(`damage` / `trap` / `down` / `killed` / `captured` / `minionDown`),
`drainEvents()`로 프레임마다 비웁니다. 렌더러는 이걸 플래시와 링으로,
UI는 숫자와 소리로 바꿉니다. 시뮬레이션은 여전히 순수합니다.

- **데미지 숫자** — HTML 오버레이. WebGL 텍스트는 폰트 아틀라스가 필요한데,
  동시에 뜨는 개수가 십수 개라 DOM이 더 낫습니다. 화상 도트는 매 프레임
  들어와서 숫자로 띄우지 않습니다(1이 벽처럼 쌓임).
- **피격 플래시** — 맞은 유닛이 잠깐 하얗게. 여러 유닛이 붙어 싸울 때
  무슨 일이 일어나는지 읽을 수 있는 유일한 신호입니다.
- **함정 링** — 발동 지점에서 퍼지는 원.
- **처치 / 생포** — 각각 다른 색 링 + "처치" / "생포!" 표시.

### 애니메이션

모델에 클립이 있으면 `AnimationMixer`로 `idle` / `walk` / `attack` / `death`를
자동 연결합니다. 클립 이름은 모델 파일명과 마찬가지로 **정규식으로 매칭**합니다
(KayKit은 `Idle`, `Walking_A`, `1H_Melee_Attack_Chop`, `Death_A` 같은 이름을 씁니다).

시뮬레이션이 유닛마다 `action`과 `facing`을 계산하므로, 모델이 들어오면
걷고 때리고 쓰러지는 것이 **추가 작업 없이** 붙습니다. 지금은 도형이라
회전만 보입니다.

### 배포 후 할 일 (순서대로)

**1. 배포**

```bash
npx -y @agent8/deploy
```

**2. 대시보드에서 상품 등록** — Verse8 → 게임 관리 페이지 → **VX Shop** 탭 → Add New Item

| 필드 | 값 |
|---|---|
| Product ID | `server.js`의 `PRODUCTS` 키와 **문자열까지 일치해야 함** |
| Product Name | 영어 권장 (예: Remove Ads) |
| Product Image | 512×512 권장 |
| Price (VX) | 100 VX ≈ $1 USD 기준으로 결정 |
| Stock Quantity | **넉넉히 크게** — 아래 주의 참고 |
| Purchase Constraints | Lifetime limit **1회** (영구 아이템이므로) |
| Active | 켜기 |

> **Stock 주의** — 문서상 Stock Quantity는 "Total available inventory",
> 즉 **유저별이 아니라 전체 재고**입니다. 디지털 영구 아이템에 100을 넣으면
> 100명이 사고 나서 품절됩니다. Lifetime 1회 제한이 1인당 중복 구매를 막아주므로,
> Stock은 예상 구매자 수보다 훨씬 크게 잡으세요.

> 상품 등록만으로는 판매되지 않습니다. 게임 코드에서 노출·구매를 구현해야 하고,
> 그 부분은 이미 [`ShopDialog.tsx`](src/ui/ShopDialog.tsx)에 있습니다.

**3. 지급 경로 검증** — 실제 결제 전에 확인

`server.js` 상단 `DEV_ACCOUNTS`에 **본인 지갑 주소만** 넣고 재배포하면,
결제 없이 실제 지급 코드(`grantProduct`)를 그대로 호출해 볼 수 있습니다.
주소는 게임 화면 좌측 하단에 표시됩니다.

```js
const DEV_ACCOUNTS = ["0x여기에_본인_주소"];
```

```
npx -y @agent8/cli call devGrantPurchase '[{"productId":"<PRODUCTS의 키>"}]'
npx -y @agent8/cli call devClearEntitlements '[]'
```

`$onItemPurchased`와 **같은 함수**를 호출하므로, 테스트한 경로가 곧 실제 경로입니다.
목록에 없는 계정은 `DEV_TOOL_DISABLED`로 거부되므로 남겨둬도 남이 악용할 수 없지만,
공개 릴리스 전에는 비우는 것을 권합니다.

**4. 실제 구매 1건 테스트** — 문서가 분쟁 예방을 위해 배포 전 충분한 테스트를 권고합니다.

### 광고

| Placement | 종류 | 트리거 | 광고 제거 영향 |
|---|---|---|---|
| `gold-refill` | 보상형 | HUD 버튼 (유저 탭) | 없음 — 항상 사용 가능 |
| `after-save` | 인터스티셜 | 저장 체크포인트 후, 최소 5분 간격 | **제거됨** |

보상형 광고는 자발적 선택이므로 광고 제거 대상이 아닙니다.
제거되는 것은 강제로 뜨는 인터스티셜뿐입니다.

M2에서 인터스티셜 트리거를 "침입 종료 후"로 옮깁니다. 지금은 침입 페이즈가
없어서 저장 체크포인트에 임시로 걸려 있습니다.

### 보상형 광고 검증 흐름

1. 클라이언트가 `Verse8Ads.showRewarded()` 호출 → `requestId` 획득
2. `requestId`만 서버로 전송 (`claimAdReward`)
3. 서버가 `https://ads-verifier.verse8.io/ads/status?requestId=...` 조회
4. `verified`일 때만 `$lock` 안에서 중복 확인 후 `$asset.mint('gold', 100)`

보상 금액은 서버의 `AD_REWARD_TABLE`에 있습니다. 클라이언트의 `result.reward`는
문서상 UX 힌트일 뿐이라 쓰지 않습니다.

> **배포 후 반드시 확인할 것** — 검증은 서버에서 `fetch`를 호출합니다.
> Agent8 서버는 isolated-vm이고 Node 내장 모듈이 금지되어 있는데, 전역 `fetch`가
> 제공되는지는 문서에서 확인하지 못했습니다. 없으면 `claimAdReward`가
> `VERIFY_UNAVAILABLE`로 실패합니다. **검증 없이 보상을 지급하지는 않습니다.**
> 배포 후 이 경로를 가장 먼저 테스트하세요.

```bash
npm run dev
```

```
      units.ts                부하 / 모험가 스탯 테이블
      traps.ts                함정 · 워든 스킬 스탯 테이블
      RaidSim.ts              결정론적 전투 시뮬레이션 (순수 로직)
  App.tsx                     HUD(탭) + 렌더러 연결
```

## 전투 시뮬레이션

`RaidSim`은 three.js도 DOM도 자체 시계도 참조하지 않는 **순수 로직**입니다.
`step()`은 항상 `SIM_DT`(1/20초)만큼만 전진하고, 프레임 수와 배속은
`useRaid`가 accumulator로 결정합니다. 같은 입력에 같은 스텝 수면 결과가 항상
같으므로, 나중에 서버가 의심스러운 침입을 시드로 재시뮬할 수 있습니다.

규칙:

- 모험가는 A* 경로를 따라 이동하고, 사거리 안에 부하가 있으면 멈춰서 싸웁니다.
- 워리어는 통로에 서서 길을 막고, 메이지는 3.2타일 밖에서 때립니다.
- 체력이 0이 되면 즉사가 아니라 **제압 3초**. 그 안에 감옥 빈자리가 있고 부하가
  곁에 있으면 생포, 아니면 사망하며 장비를 떨굽니다. 제압된 모험가는 이동도
  공격도 못 하고, 부하와 함정의 표적에서도 빠집니다.
- 코어 도달 = 돌파, 파티 전멸 = 격퇴, 180초 경과 = 격퇴(교착 방지).
- **입구에서 코어까지 길이 없으면 침입을 시작할 수 없습니다.** 코어를 벽으로
  막아버리는 것이 무상 승리가 되지 않도록 클라이언트와 서버 양쪽에서 막습니다.

## 서버 검증 (침입)

기획서의 3단 절충을 그대로 구현했습니다.

1. **파티는 서버가 만든다** — `startRaid`가 위협도로 파티를 편성하고 `raidId`를
   발급합니다. 클라이언트가 쉬운 웨이브를 고를 수 없습니다.
2. **결과는 범위로 검증** — `finishRaid`의 `killed`는 서버가 발급한 파티 크기로
   클램프됩니다. 과장 보고해도 완벽한 방어 이상은 못 받습니다.
3. **지급은 서버가 한다** — 보상·약탈 모두 서버 테이블로 계산해
   `$asset.mint` / `$asset.burn`을 서버가 실행합니다. `raidId`는 정산 후
   폐기되어 재사용할 수 없습니다.

부하·함정·방 배치도 서버가 다시 검증합니다 — 통로 타일 위에만, **한 칸에 하나**,
방은 2×2를 통째로 점유. 비용은 **새로 추가되거나 종류가 바뀐 것**에만 부과되므로,
기존 id를 재사용해 싼 것을 비싼 것으로 바꿔치기할 수 없습니다.
회수는 무료지만 환불도 없습니다.

부하 부활도 서버가 관리합니다. 침입에서 쓰러진 부하는 `revivesAt`이 찍히고,
`startRaid`가 아직 못 일어난 부하를 제외한 명단(`availableMinionIds`)을 돌려줍니다.
클라이언트가 죽은 부하를 출전시킬 수 없습니다.

**전향한 부하는 클라이언트가 만들 수 없습니다.** `convert` 타입 부하는 서버가
감옥에서 꺼내 배치할 때만 생기고, 이전 세이브에 없던 `convert` id가 올라오면
`ILLEGAL_CONVERT`로 거부됩니다. 직업·레벨·부활 시각도 클라이언트 값을 버리고
이전 세이브에서 가져옵니다.

**노획 무기도 검증합니다.** 장착하려는 무기가 실제 노획 목록에 있어야 하고,
한 무기는 한 부하만 들 수 있습니다. 위반하면 조용히 해제됩니다.

**생포 인원은 서버가 발급한 감옥 칸으로 잘립니다.** `startRaid` 시점의 `jailFree`가
상한이고, 같은 모험가가 사망·생포 양쪽에 보고되면 생포가 버려집니다.

방 효과는 클라이언트에도 같은 계산이 있지만(UI 표시용) **서버 값이 항상 우선**입니다.

## 개발용 콘솔 핸들

개발 빌드에서만 `window.__dw`가 노출됩니다(`import.meta.env.DEV` 가드).

```js
__dw.digTile(3, 6)
__dw.placeMinion('warrior', 5, 6)
__dw.placeTrap('flame', 7, 6)
__dw.placeRoom('treasury', 3, 5)   // 2x2 통로 필요
__dw.removeAt(7, 6)
await __dw.saveNow()
await __dw.startRaid()
__dw.useSkill('blessing')
__dw.raidState

// 애니메이션 루프 없이 전투만 결정론적으로 돌리기
const { RaidSim, findPath } = __dw.sim
const path = findPath(__dw.grid, __dw.meta.entrance, __dw.meta.core)
const sim = new RaidSim({ minions: __dw.minions, party, path, seed: 1 })
while (sim.state.status === 'running') sim.step()
```

## 설계상 중요한 결정

**골드는 세이브에 없습니다.** `$asset`(`mint`/`burn`/`has`)으로 관리합니다.
Verse8 문서가 화폐·자원에 `$asset`을 권장하며, 세이브와 화폐를 분리하면
세이브 조작으로 돈을 늘리는 경로가 막힙니다.

**굴착은 클릭마다 서버에 보내지 않습니다.** `remoteFunction`이 약 10회/초로
제한되기 때문에, 굴착은 클라이언트 메모리에 쌓았다가 세 시점에만 전송합니다.

1. 체크포인트 — 건설 확정, 64칸 도달
2. 60초 오토세이브
3. 탭 이탈 (`visibilitychange` / `pagehide`)

**서버가 비용을 다시 계산합니다.** 클라이언트가 보낸 합계를 믿지 않고,
이전 세이브와 새 그리드의 차이를 서버가 직접 세어 비용을 매깁니다.
`ROCK → FLOOR` 전이만 허용하므로 통로를 되메우거나 입구·코어를 옮길 수 없습니다.

**그리드는 RLE로 저장합니다.** 24×24까지 커지면 셀 배열이 세이브에서 가장 큰
덩어리가 되는데, 타일 종류가 4개뿐이라 압축률이 매우 높습니다.

**구매는 클라이언트가 절대 지급하지 않습니다.** 엔타이틀먼트를 주는 곳은
`$onItemPurchased` 하나뿐입니다. 클라이언트의 `onClose` 콜백은 "다시 읽어와라"는
신호일 뿐이고, 지급 권한이 없습니다. Verse8이 콜백을 재시도할 수 있으므로
`purchaseId`를 기록해 두고 `$lock`으로 중복 지급을 막습니다.

**던전 초기화는 구매를 취소하지 않습니다.** `resetGame`은 진행도만 되돌리고
엔타이틀먼트는 그대로 둡니다.

### 벽은 타일이 아니라 모서리에 세웁니다

KayKit의 `wall`은 4×4×1 **패널**입니다. 1×1 돌덩이가 아니라 통로 가장자리에
세우라고 만든 물건이라, 타일마다 하나씩 놓으면 길게 늘어져 보입니다.

그래서 렌더러는 **통로 타일의 네 변 중 암반과 접한 곳에만** 벽 패널을 세웁니다.
파낸 통로가 돌을 깎아낸 것처럼 보이는 이유입니다. 암반 자체는 여전히 단색
블록입니다 — 던전 킷에 1×1 돌 큐브라는 물건이 없습니다.

### 애니메이션은 공용 리그 파일에 있습니다

KayKit 2.0 캐릭터 `.glb`에는 클립이 **들어 있지 않습니다.** 같은 리그를 쓰는
캐릭터가 공유하도록 `Animations/gltf/Rig_Medium/`에 분리돼 있습니다.

`ModelLibrary.loadSharedClips()`가 이 파일들을 한 번 읽고, 클립이 없는 캐릭터에
붙여 줍니다. 검증 결과 **클립의 본 23개가 캐릭터 본과 100% 일치**(누락 0)해서
리타게팅 없이 그대로 적용됩니다.

무료 티어에는 **공격 클립이 없습니다.** `Idle_A` / `Walking_A` / `Death_A`는
있고, 공격은 가장 근접한 `Interact`로 대체했습니다. 유료 애니메이션 팩을
넣으면 패턴 우선순위상 진짜 공격 클립이 자동으로 우선됩니다.

### 왜 파일명을 하드코딩하지 않았나

팩을 수동으로 받다 보니 정확한 파일명을 미리 알 수 없고, 팩이 업데이트되면
이름이 바뀝니다. 그래서 `src/game/assets/ModelLibrary.ts`가 **정규식 패턴**으로
매니페스트를 검색합니다. 예를 들어 워리어는 `/skeleton.*warrior/` →
`/skeleton_warrior/` → `/^skeleton(?!.*mage)/` 순으로 시도합니다.

패턴이 안 맞는 모델이 있으면 `MODEL_PATTERNS`에 한 줄 추가하면 됩니다.
매칭 결과는 `ModelLibrary.report()`로 확인할 수 있습니다.

**에셋이 없어도 게임은 그대로 돌아갑니다.** 매니페스트가 비어 있으면 지금처럼
도형으로 렌더링되고, 모델이 들어오면 자리에서 교체됩니다.

### 사운드

같은 방식입니다. `.ogg` / `.mp3` / `.wav`를 `public/assets/audio/` 아래
아무 폴더에나 넣고 `npm run assets`를 다시 실행하면 파일이 쓰입니다.

추천 CC0 팩 (전부 Kenney, 직접 다운로드 가능):
[Interface Sounds](https://kenney.nl/assets/interface-sounds) ·
[Impact Sounds](https://kenney.nl/assets/impact-sounds) ·
[Music Jingles](https://kenney.nl/assets/music-jingles)

**파일이 없어도 소리는 납니다.** `src/game/audio.ts`가 WebAudio로 각 큐를
합성합니다. 이건 나중에 지울 임시방편이 아니라, 다운로드 없이도 게임이 들리게
하는 기본 경로입니다. 파일을 넣으면 같은 큐 이름으로 그대로 대체됩니다.

큐: `click` `place` `dig` `error` `raidStart` `hit` `trap` `skill` `victory` `defeat`

## 연구 트리

시작 시점에 쓸 수 있는 것은 **워리어 / 가시 함정 / 보물방** 셋뿐입니다.
나머지는 전부 연구로 열립니다 — 이게 저장형 게임의 진행 축입니다.

| 분류 | 노드 |
|---|---|
| 해금 | 강령술(메이지) · 기계 장치(화살) · 굴착 공학(낙석) · 지옥불(화염) · 병영/금고/작업장/제단/구속 설계 |
| 강화 | 뼈 단련 I·II (부하 공격력) · 불사의 살점 I·II (부하 체력) · 정밀 격발 I·II (함정 피해) |
| 확장 | 심층 굴착 I·II (던전 폭 12 → 16 → 20) |

티어는 **누적이 아니라 대체**입니다. I과 II를 모두 가지면 II 값만 적용됩니다.

던전 확장은 공짜 공간이 아닙니다. 새 구간은 전부 암반이고 코어가 뒤로 물러나므로,
파던 길을 더 깊이 다시 파야 합니다.

## 위협도 곡선

| 위협도 | 파티 | 보상 배율 |
|---|---|---|
| 0 | 1명 | ×1.00 |
| 3 | 2명 | ×1.15 |
| 6 | 3명 | ×1.30 |
| 9 | 4명 | ×1.45 |
| 12+ | 5명 (상한) | ×1.60 이상 |

위협도는 격퇴하면 오르고 돌파당하면 내려가며, **20분마다 1씩 자연 감쇠**합니다.
보물방은 위협도를 더 올립니다. 즉 위협도는 벌칙이 아니라 **플레이어가 돌리는
난이도/보상 손잡이**입니다. 감쇠가 있어 한 번 어려워지면 영영 못 빠져나오는
상황이 생기지 않습니다.

개별 모험가 레벨은 위협도와 별개로 **격퇴당할 때마다 오릅니다**(숙적 시스템).
난이도가 두 축으로 오르는 구조입니다.

## 순위표

`dungeon_leaderboard` 글로벌 컬렉션에 **계정당 한 행**(`__id: account`)을 두고,
`orderBy: [{ field: "wavesRepelled", direction: "desc" }]`로 상위 20명을 읽습니다.
문서상 `filters`와 `orderBy`는 함께 쓸 수 없어서, 본인 행은 질의 대신 id로 직접
가져옵니다.

점수는 **세이브에서 읽습니다.** 클라이언트가 보낸 숫자는 쓰지 않고, 보낼 수
있는 것은 닉네임뿐입니다.

한 판 점수가 아니라 **누적 격퇴 횟수** 기준입니다. 저장형 게임을 자기 순위표로
런 파밍 게임으로 바꾸지 않기 위한 선택이고, 등록도 선택 사항입니다.

## 알려진 이슈

- 번들이 약 919KB(gzip 256KB)입니다. 대부분 three.js + GLTFLoader이며,
  동적 import로 분리하는 것이 남은 최적화입니다.
- **배포는 하지 않았습니다.** 배포는 프로젝트 소유자가 직접 합니다.
  따라서 서버 코드(`startRaid` / `finishRaid` / `researchNode` / `submitScore` /
  `getRankings` / 전향 정산)는 아직 실제로 실행된 적이 없습니다.
  배포 후 가장 먼저 확인해야 할 부분입니다.
- Browser pane이 숨겨진 개발 환경에서는 `requestAnimationFrame`이 멈춰
  실시간 침입 화면을 육안으로 확인하지 못했습니다. 시뮬레이션 자체는
  애니메이션 루프 없이 직접 스텝해 수치로 검증했습니다.
- 탭이 백그라운드로 가면 `requestAnimationFrame`이 멈춰 침입도 멈춥니다.
  복귀 시 프레임당 스텝 수 상한과 델타 클램프(0.25초)가 있어 몰아서 돌지는
  않습니다. 게임이 일시정지되는 동작이라 의도한 대로 두었습니다.
- `@agent8/gameserver@1.10.2`의 peer 의존성이 React 18이라 React를 18.3.1로
  고정했습니다. Vite 템플릿 기본값인 19를 쓰면 설치가 실패합니다.
